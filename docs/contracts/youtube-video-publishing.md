# YouTube video publishing — SYN-SOC-006

**Status:** Implemented — PR pending review. This is an explicit owner-controlled upload of one saved, same-Brand MP4 to a connected YouTube channel. An assembled Reel is an eligible source. No scheduling, automatic upload, or separate Shorts API exists.

Official references checked **2026-10-28**: [videos.insert](https://developers.google.com/youtube/data/reference/rest/v3/videos/insert), [resumable protocol](https://developers.google.com/youtube/data/guides/using_resumable_upload_protocol), [videos resource](https://developers.google.com/youtube/data/reference/rest/v3/videos), [Google OAuth web server](https://developers.google.com/identity/protocols/oauth2/web-server), [Shorts eligibility](https://support.google.com/youtube/answer/15424877?hl=en). The actual Google application, consent-screen audit, quotas and channel entitlement require separate live verification. The current reference states `videos.insert` consumes one unit of the Video Uploads quota bucket and limits calls to 100/day; account-specific quotas may differ.

| ID | Rule / acceptance | Test subjects and limitation |
|---|---|---|
| YTP-001 — Channel readiness | Discovery requests `youtube.readonly`; explicit YouTube-only reauthorization additionally requests `youtube.upload`. A connected, unexpired grant must contain both scopes. A read-only `channels?mine=true` call must return the selected channel ID before upload. Missing/denied access fails closed; a configured client is not proof of API entitlement. | Scope, token refresh preservation, missing/expired/revoked grant, wrong channel; live OAuth not verified. |
| YTP-002 — Private source | Exactly one same-Brand MP4, including `REEL_ASSEMBLED`, at most 20 MiB. The server re-inspects private bytes with ffprobe and computes SHA-256 by streaming. The original is never changed. | Foreign/missing/corrupt file, metadata mismatch, byte digest, unchanged source. |
| YTP-003 — Exact review | Explicit title (1–100 characters; no `<`/`>`), saved draft body as description (at most 5000 UTF-8 bytes; no `<`/`>`), selected channel and `private`/`unlisted`/`public` are frozen. `private` is the default. Source aspect ratio and duration up to three minutes yield a **possible Shorts** hint, never a guarantee. | Limits, explicit visibility, stale draft/media, square/vertical eligibility. Copyright/Content ID and special channels may change classification. |
| YTP-004 — Owner confirmation | Prepare, GET, draft Save and media preview make no provider write. Only `confirm:true` claims an upload. The Studio states that public/unlisted uploads may be externally visible. | No-write reads, stale review and confirmation tests. |
| YTP-005 — Resumable upload | One `videos.insert?uploadType=resumable` session is created. Its validated `Location` is AES-256-GCM encrypted. The same session accepts bounded streamed chunks; `308` and a status probe determine the confirmed next byte. A failed/interrupted write is never blindly replayed. | Fixed host/path, redirects off, 308/Range, probe, same-session resume, expired session, timeout and status codes. Session lifetime is provider-controlled. |
| YTP-006 — Idempotency | Unique owner request ID, row lock and conditional `READY→PUBLISHING` claim admit one session initiation. Ambiguous initiation/completion remains `UNCERTAIN`; no new session is started automatically. A known session may be explicitly probed and resumed. Expired/unknown sessions require operator evidence before any new initiation. | Double click, concurrency, crash/restart, uncertain outcomes, no duplicate `videos.insert`. |
| YTP-007 — Outcome/history | `Publication` stores immutable title/description/channel/privacy/source digest, encrypted session, confirmed byte offset, provider ID and safe status. An upload response with video ID is verified via `videos.list`; processing and privacy are shown honestly. Only a verified ID yields a watch URL. | 201, processing, private/unlisted/public, history and safe failures. A provider ID does not imply publicly playable video. |
| YTP-008 — Studio | A compact draft-editor panel chooses a same-Brand MP4, connected channel, title and privacy. It previews the private source, shows the Shorts hint, exact review, progress, explicit continue/check and history. Unsaved draft edits block review. | Next→Nest smoke and desktop/390px browser subject; do not infer visual acceptance from a build. |
| YTP-009 — Isolation/security | Session and Origin/CSRF, owner/Brand/channel/media boundaries, encrypted OAuth and upload-session data, bounded provider responses, strict Google destination validation, safe errors and no public media URLs. Existing social publishing flows remain unchanged. | Real PostgreSQL and deterministic provider mocks; no real Google upload in CI. |

`READY` is a local review intent. `PUBLISHING` identifies one claimed attempt; an interrupted claim becomes `UNCERTAIN`. `PROCESSING` means YouTube returned a video ID but has not yet confirmed processing success. `PUBLISHED` means a read-only lookup verified the ID, channel and privacy; it does **not** mean public visibility for private/unlisted uploads. `FAILED` is a definite provider rejection. Resume and check are explicit actions against the existing encrypted session/known video ID. No request starts a second session for an uncertain intent.

# LinkedIn member publishing — SYN-SOC-005

**Status:** Implemented on feature branch; PR pending review. **Scope:** immediate public text or one JPEG/PNG image post to a connected LinkedIn **member** account only. The saved Content Draft body is the exact text. No organization Page, scheduling, automatic posting, video or live LinkedIn result is claimed.

Official documentation checked **2026-10-28**: [Getting access](https://learn.microsoft.com/en-us/linkedin/shared/authentication/getting-access), [Share on LinkedIn](https://learn.microsoft.com/en-us/linkedin/consumer/integrations/self-serve/share-on-linkedin), [versioned Posts API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/posts-api?view=li-lms-2026-10), [Images API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/images-api?view=li-lms-2026-02), [Post schema](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/post-api-schema?view=li-lms-2026-09), [little-text grammar](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/little-text-format?view=li-lms-2026-01), [API versioning](https://learn.microsoft.com/en-us/linkedin/marketing/versioning). The Share on LinkedIn guide still illustrates older `v2/ugcPosts`; SYNVARO uses the current `/rest/posts` API with `Linkedin-Version: 202610` and `X-Restli-Protocol-Version: 2.0.0`. Account-level entitlement to this endpoint cannot be inferred from documentation or a configured client ID; a real grant/write requires separate acceptance.

| LIP-004 — Explicit confirmation | Prepare, history, readiness, page load and draft save have no LinkedIn write. Studio shows exact member, text and image. Only `confirm:true` can start the single publish attempt. | Confirmation input, UI review, no GET side effects |

| LIP-006 — Ledger | Existing `Publication` stores immutable text/member/Brand/draft/media fields. ## Lifecycle and limitations

`READY` is only a local review intent. `PUBLISHING` is the sole claimed attempt. A valid Posts API 201 and post URN yield `PUBLISHED`. Definite provider rejection yields `FAILED`; ambiguous network/timeout/5xx or missing post ID yields `UNCERTAIN`. GET never resends. Each provider call has a 15-second deadline; Next.js confirmation allows 135 seconds for the bounded sequence, and a claimed operation is considered interrupted only after 120 seconds. Manual operator reconciliation needs independently verified LinkedIn evidence; no public reconciliation endpoint exists. An image upload can leave a remote unused image without a visible post. The account's actual Share on LinkedIn product access, write-only image read fallback, rate limits, text acceptance and live publication have **not** been verified with a real LinkedIn account. Mocks demonstrate local behavior only. The LinkedIn app must have Share on LinkedIn access, a matching authorized member and explicit `w_member_social`; organization publishing requires a separate scope/product/contract.

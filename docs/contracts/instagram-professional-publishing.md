# Instagram professional single-image publishing — SYN-SOC-004

**Implementation state:** Implemented on `feat/syn-soc-004-instagram-publishing`; PR pending review. This contract does not claim a live Meta authorization or post.

## Provider boundary

Checked 2026-10-28 against Meta's [Instagram API with Facebook Login collection](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api). The Meta collection confirms Page-linked Business/Creator accounts, the four discovery/publishing grants, Page access tokens, container status and a distinct `media_publish` result. The canonical [single-image content-publishing reference](https://developers.facebook.com/docs/instagram-platform/content-publishing) returned HTTP 429 during this review; its current image-specific parameters and limits still require direct verification before a live post. The 8 MB and aspect-ratio checks below are conservative SYNVARO limits, not a claim about Meta's full allowance. SYNVARO uses the existing fixed Graph API `v26.0` endpoint pattern; it does not implement Instagram Login, personal accounts, Stories or Reels publication.

| Behavior | Business rule and acceptance | Test subject |
| --- | --- | --- |
| **IGP-001 — Eligibility** | Only a connected professional Instagram account from the draft Brand can be selected. Publishing reauthorization explicitly adds `instagram_content_publish` to Instagram's Facebook Login request. Readiness checks live user grants, linked Page content task, Page/IG ID and Page token. PNG conversion is deferred; originals are unchanged. | JPEG, PNG rejection, invalid bytes, size/dimensions, changed source |
| **IGP-003 — Snapshot** | A `Publication` stores the exact saved draft caption, destination IG ID/name, owned MediaAsset ID, MIME/size/SHA-256 and draft revision time. A changed draft or source fails confirmation. Unsaved editor text is never submitted. | Stale draft, immutable snapshot, integrity |
| **IGP-004 — Approval** | Preparing is read/review only. A separate authenticated `confirm: true` POST creates one container. A further explicit POST publishes a finished container. GET, refresh and status checks never create or publish. | No provider write before approval, Origin/session, page load |
| **IGP-005 — Provider lifecycle** | `POST /{ig-id}/media` returns a container ID, `GET /{container-id}?fields=id,status_code` observes processing, and `POST /{ig-id}/media_publish` returns a separate published media ID. `IN_PROGRESS` is durable; `FINISHED` enables final action; `ERROR`/`EXPIRED` fail. Reload resumes the existing record and never creates another container. | Container/status/media IDs, processing, expiry, reload |
| **IGP-006 — Image delivery** | Meta receives only an HTTPS URL with a 30-minute HMAC signature bound to publication ID, source SHA-256 and expiry. The public route serves that validated JPEG only while its publication is processing. No general public Media Library URL, arbitrary URL fetch or filesystem path is exposed. Missing public HTTPS origin/key fails closed. | Valid/invalid/expired token, changed image, private media regression |
| **IGP-007 — Duplicate/uncertain** | PostgreSQL unique `(userId, requestId)` and atomic state claims prevent duplicate write transitions. Ambiguous container creation or `media_publish` yields `UNCERTAIN`; no automatic retry. A lost container response is not reconstructed. A stored container ID can be inspected read-only, but an uncertain publish requires independent Meta evidence and audited operator reconciliation. | Concurrent double click, timeout, no resend, request ID reuse, platform-scoped reconciliation |
| **IGP-008 — History** | Owner-scoped history shows safe status, immutable snapshot, container ID/status and published media ID only when returned. No unverified permalink is fabricated. | History, post ID, foreign 404 |
| **IGP-009 — Security** | Existing session, Origin/CSRF, encrypted Page token and server-side Brand ownership apply. Provider URL is fixed, errors are categorized without returning raw bodies, and no operation publishes automatically. | Cross-Brand/Org, missing auth, sanitized failure, unchanged source |

## API and configuration

Authenticated routes: `GET /contents/:id/instagram-publications/readiness`, `GET|POST /contents/:id/instagram-publications`, `GET /instagram-publications/:id`, and `POST /instagram-publications/:id/{confirm,check,publish}`. The narrow `GET /instagram-delivery/:id/:expiry/:signature` is intentionally unauthenticated so Meta can fetch the JPEG; the signed URL is a short-lived bearer capability for exactly one publication and source digest. Keep it out of browser history and logs. All routes are in OpenAPI.

Set `INSTAGRAM_MEDIA_PUBLIC_ORIGIN` to the exact externally reachable HTTPS origin serving the NestJS delivery route, and `INSTAGRAM_DELIVERY_SIGNING_KEY` to a private random 32-byte base64 key. Keep the key stable through the 30-minute delivery window and back it up. Do not set a localhost origin. Validate external TLS/routing and Meta retrieval in owner-approved live acceptance; a syntactically valid origin is not proof of reachability.

## Limits and unresolved acceptance

The 30-minute signed URL window is deliberately bounded. A delayed Meta fetch after expiry fails rather than exposing the source longer. There is no general image transcoder, carousel, video/Story publishing, scheduler or automated reconciliation. If `media_publish` times out, the exact external outcome requires read-only provider/operator evidence; never resubmit the container automatically. Meta app review, Page-linked professional account, correct task/grants and one owner-approved harmless live post remain external acceptance. Deterministic mocks prove local behavior only.

For an independently verified uncertain outcome, use `node --env-file=.env scripts/reconcile-instagram-publication.mjs <id> PUBLISHED <ig_media_id> <evidence_ref> <operator>` or `FAILED -` only when evidence proves no post. The script records an audit reference and cannot change Facebook rows. A timeout alone is not proof of failure.

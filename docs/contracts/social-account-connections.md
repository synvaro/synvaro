# Social account connections — SYN-SOC-001

SYN-SOC-001 merged in PR #27. Verified against official provider documentation on 2026-10-27. Connection is not permission to publish. A locally configured adapter is not proof of provider app approval, account entitlement or successful live OAuth. SYN-SOC-002 adds a separate Facebook-only publishing reauthorization path; see [PUB-001–008](facebook-page-publishing.md).

| Behavior | Business rule and acceptance | Test subjects |
|---|---|---|
| SOC-001 — Supported platforms | Facebook Pages, Page-linked professional Instagram accounts, LinkedIn members and YouTube channels are discoverable. Personal Instagram and LinkedIn organizations are not connected by this slice. | Catalog truth; account type; no publishing eligibility claim |
| SOC-002 — OAuth authorization | Owner chooses a Brand and platform. Server generates 256-bit state, hashes it in PostgreSQL, binds it to the current session hash and Brand, expires it after ten minutes and consumes it atomically once. Google authorization uses PKCE S256. Exact redirect comes from WEB_ORIGIN. | Consent denial, expired/replayed state, foreign session, Origin/CSRF, invalid redirect configuration |
| SOC-003 — Account discovery | Provider returns only authorized Page, Instagram professional account, member or channel metadata. Discovery is visible only to the initiating session. No account is associated automatically. | Empty discovery, malformed provider data, safe metadata, no token response |
| SOC-004 — Brand association | Owner explicitly chooses a discovered account. Global unique (platform, external ID) blocks connections to another Brand. Reauthorization updates credentials only for the same Brand. | Explicit selection, duplicate/cross-Brand conflict, concurrent association |
| SOC-005 — Token storage and lifecycle | AES-256-GCM application encryption uses versioned key IDs. Access/refresh tokens are encrypted, never returned. Expired access is shown as EXPIRED; YouTube refresh is explicit where a refresh token exists. Other unsupported refresh paths require reauthorization. Expired OAuth attempts are removed opportunistically. | Ciphertext and key rotation, expiration, missing refresh, credential leakage |
| SOC-006 — Connection status | A connected row records account type, provider-reported scopes when supplied, expiration and last validation. Missing scope metadata remains unknown; it is never inferred from requested scopes. Current status does not claim live provider access or publishing eligibility. | List safety, expiry, revoked provider response, stale status |
| SOC-007 — Disconnect and reauthorize | Disconnect removes active credentials immediately. Accounts without publication history are deleted; a Facebook Page with historical publications is retained as redacted `DISCONNECTED` metadata. Google revocation is attempted when the last account from a grant is removed; Meta revocation is attempted only when no other connected Meta account remains for that owner, to avoid revoking another linked Page. LinkedIn consumer revocation is not verified. Reauthorization requires fresh consent and explicit selection. | Unauthorized disconnect, local deletion/redaction, revocation failure, reconnect |
| SOC-008 — Isolation and safety | All owner actions use the existing session and Origin guard. Unknown and foreign resources return indistinguishable 404 responses. OAuth callback can run without a browser session cookie because Strict SameSite blocks it after provider redirect; final account selection requires the original session. No token or raw provider error appears in URL, response or logs. | Session ownership, CSRF, state replay, provider error sanitization, external redirect |

## Provider scope and prerequisites

- **Meta:** Standard Facebook Login requests `pages_show_list` for Pages; Instagram additionally requests `pages_read_engagement` and `instagram_basic`. SYN-SOC-002 has distinct explicit Facebook Page publishing reauthorization requesting `pages_manage_posts`; SYN-SOC-004 adds a distinct explicit Instagram publishing reauthorization requesting `instagram_content_publish`. Neither widens the other's ordinary grant. Page discovery uses `/me/accounts` and `instagram_business_account`; Instagram credentials retain their linked Page ID after fresh authorization. Existing records without that ID require a live linkage check. Meta app review/Live mode remain external prerequisites. Page and user tokens stay encrypted. [Meta Instagram API](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api), [Page token discovery](https://www.postman.com/meta/instagram/request/0vuw3vk/get-access-tokens-of-pages-you-manage).
- **LinkedIn:** `openid profile` and OIDC `/v2/userinfo` connect a member only. SYN-SOC-005 adds an explicit LinkedIn-only `w_member_social` publishing reauthorization; ordinary connection remains unchanged. See [LIP-001–009](linkedin-member-publishing.md). Organization administrator discovery needs separately approved organization permissions; this slice does not claim that access. Consumer refresh/revoke APIs are not assumed. [Authorization code](https://learn.microsoft.com/en-us/linkedin/shared/authentication/authorization-code-flow), [OIDC](https://learn.microsoft.com/en-us/linkedin/consumer/integrations/self-serve/sign-in-with-linkedin-v2), [organization permissions](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/organization-access-control-by-role?view=li-lms-2026-03).
- **YouTube:** Google web OAuth with `youtube.readonly`, offline access and explicit channel discovery via `channels.list(mine=true)`. SYN-SOC-006 adds an explicit YouTube-only publishing reauthorization that also requests `youtube.upload`; ordinary connections retain read-only scope. Google may omit a new refresh token during later consent, so the encrypted token for the *same channel and Brand* is preserved without carrying over old granted scopes. Upload readiness rechecks the selected channel with the current access token. See [YTP-001–009](youtube-video-publishing.md). Google OAuth consent configuration, test users, scope verification and channel access are external prerequisites. [Google web OAuth](https://developers.google.com/identity/protocols/oauth2/web-server), [YouTube server OAuth](https://developers.google.com/youtube/data/guides/auth/server-side-web-apps), [channels](https://developers.google.com/youtube/data/guides/implementation/channels).

## Limits

No live platform authorization is claimed from deterministic mocks. LinkedIn organizations, personal Instagram, non-Facebook publishing scopes, background token validation/refresh, scheduled cleanup and multi-Brand sharing are outside this slice. Disconnect cannot prove external revocation if the provider lacks a verified API or the revocation request fails. Provider access may be revoked before the stored expiry; SYN-SOC-002 checks Facebook publishing readiness live for each attempt. Tokens and private keyring must be backed up separately from PostgreSQL; losing a key prevents decryption of existing grants.
